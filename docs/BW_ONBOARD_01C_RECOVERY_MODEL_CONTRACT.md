# BW-ONBOARD-01C — Recovery Model Tutorial Integration

## Purpose

Teach the BreakWave recovery model inside the existing replayable
**Teach Me BreakWave** experience without creating a new navigation model,
new recovery record, new entitlement, or replacement onboarding system.

The organizing model is:

**RECOGNIZE → INTERRUPT → REDIRECT → REINFORCE**

User-facing language may also explain it as:

**Notice it → Break it → Choose differently → Strengthen what works**

The model is the behavioral spine of the existing product, not four new
features or four new tabs.

## Product mapping

- **Recognize** — Log, triggers, check-ins, reflections, and future pattern
  observations help the user notice what keeps showing up.
- **Interrupt** — Rescue remains the heart of BreakWave and the immediate
  intervention when an urge is building.
- **Redirect** — Next Right Actions and recovery tools help the user choose
  a healthier response after interruption.
- **Reinforce** — Victories, encouragement, and remembering what helped
  strengthen responses worth repeating.

## Tutorial contract

BW-ONBOARD-01C preserves the existing six compact Teach Me sections and
their replay/completion behavior. The opening section introduces the model
and the existing sections explain how current BreakWave features support it.

The tutorial must not imply that the user has to learn theory before using
Rescue. Rescue remains immediately available regardless of tutorial state.

## Practice Rescue contract

Practice Rescue demonstrates the model without becoming real recovery data:

1. **Recognize** — name the practice wave.
2. **Interrupt** — bring the Personal Why into view and slow the body.
3. **Redirect** — choose one practice Next Right Action.
4. **Reinforce** — notice that choosing a different response is worth
   practicing.

Practice remains clearly labeled **PRACTICE MODE** and **No Save**.

It must not:
- create or edit a Log entry;
- change insights, streaks, recovery plans, tutorial progress, or entitlement;
- edit the Personal Why;
- open messaging, calling, emergency, Support, or other external actions.

The existing sandbox side-effect protections from BW-ONBOARD-01B2 remain
authoritative.

## Access and language

Core recovery remains genuinely useful without Plus. Rescue, basic logging,
privacy controls, and essential support remain available according to the
existing BreakWaveAccessPolicy.

Plus may deepen pattern insight, personalization, saved planning, guided
routines, reports, journeys, and longer-term analysis. Plus does not unlock
basic recovery.

Tutorial language should emphasize agency and learning rather than shame,
failure, streak-reset logic, or all-or-nothing recovery.

## Scope restraint

BW-ONBOARD-01C does not redesign Home, Log, Support, or the real Rescue
screen. It does not change onboarding invitation behavior, tutorial storage,
recovery mode storage, access policy, billing, or Plus implementation.

Future user-facing milestones should continue to ask:

**How does this screen help the user Recognize, Interrupt, Redirect, or
Reinforce?**
